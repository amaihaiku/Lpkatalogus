## 2024-05-18 - Row-level Dirty Checking in ZX Spectrum Renderer
**Learning:** The ESP32's SPI and memory bus can be saturated by frequent small updates. In a ZX Spectrum emulator, entire character rows are frequently unchanged between frames. Iterating through all 768 character cells and checking each individually (`bool dirty = false`) incurs significant overhead, particularly the inner loop computing scanlines.
**Action:** Implement a fast-path row-level dirty check using `memcmp` across the 32-byte (256 pixel) scanlines before attempting to decode and draw colors to the TFT. By skipping unchanged rows entirely, we avoid extensive nested loop processing, decoding logic, and SPI pushes. Benchmarks showed processing unchanged frames dropped from ~43us to ~11us per frame on the ESP32.
