## 2025-02-18 - [ZX Spectrum Renderer Optimization]
**Learning:** [ZX Spectrum screen rendering can be significantly bottlenecked by redundant character-level pixel updates. A common pattern in emulators is to check for dirty state per character cell, which requires many small checks. However, comparing entire character rows (32 columns) at once using memcmp is much faster due to the ESP32's 32-bit architecture and optimized memory functions. Also, scanline offsets in the ZX spectrum screen memory layout are constant across a character row and should be hoisted out of the column loop.]
**Action:** [When optimizing pixel rendering loops, look for opportunities to do bulk memory comparisons (memcmp) on larger logical blocks (like full rows) rather than cell-by-cell comparisons. Hoist complex address calculations out of inner loops whenever possible.]
