## 2024-06-20 - Double Buffering required for true DMA parallelism in display transfers
**Learning:** When using DMA for display transfers (`pushPixelsDMA` or similar), a single shared buffer offers zero parallelization benefit, as the CPU must still wait for the previous DMA transfer to complete (`dmaWait()`) before preparing the next chunk of data. True parallelization on this architecture is achieved by utilizing double buffering.
**Action:** When implementing or optimizing DMA routines, always allocate and utilize an array of at least two buffers (e.g., `_transactions[2]`) with `MALLOC_CAP_DMA`. Prepare data in the inactive buffer while the active buffer is being transferred by DMA. Call `dmaWait()` *after* preparing the inactive buffer and immediately *before* sending it, to maximize CPU/DMA overlap.
