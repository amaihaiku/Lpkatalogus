## 2023-10-26 - Double buffering for SPI DMA display driver
**Learning:** When attempting to use DMA (`pushPixelsDMA`) for display transfers, using a single shared buffer provides zero parallelization benefit because you have to wait for the previous DMA transaction to finish before writing the next row. True DMA performance gains in this architecture require double-buffering and allocating the buffers with `heap_caps_malloc(..., MALLOC_CAP_DMA)` to ensure they are accessible by the DMA controller. This allows the CPU to compute the next row's pixels while the previous row is being transferred by the DMA controller.
**Action:** When implementing SPI DMA screen updates, always allocate two buffers in DMA memory and swap them each iteration to parallelize rendering and data transfer.
