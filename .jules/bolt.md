## 2024-06-07 - ZX Spectrum Screen Rendering Optimization
**Learning:** The emulator renders its screen line-by-line using a complex pixel expansion process from character blocks (8x8 pixels). In many screens (like main menus or text adventure games), large swathes of the screen are entirely static. A simple dirty-checking mechanism per attribute/pixel block is too granular, leading to overhead.
**Action:** By checking an entire 32-character block row (both attributes and contiguous pixel memory chunks using `memcmp`) for changes *first*, we can establish a fast-path that entirely skips the pixel-expansion loop for static screen regions, achieving significant cycle savings per frame. Always look for ways to coalesce dirty-checks into larger contiguous blocks for software rendering tasks.
